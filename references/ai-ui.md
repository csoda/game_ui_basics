# AIがゲームUIを作るときに気をつけること

説明文を書き足す前に、プレイヤーがその場で何を見て、どう動くかを考える。採掘中なら「もう一段掘るか、今補充するか」。この判断に使わない文字は、常に出す必要がない。

## 1. GPT語を操作ラベルにしない

- 「深く、強く。」「探索を、次の段階へ。」のような、読点で区切って雰囲気を出すコピーを勝手に足さない。「新たな可能性が解放されました」のように、何が変わったか分からない文も避ける。
- ボタンは押した結果が分かる言葉にする。「旅の準備を整える」より「装備を選ぶ」。「実行」より「鉱石を売る」。取り消せない操作を「OK」だけで確定させない。
- 同じ物には同じ名前を使う。HUDが「燃料」なら、ボタン周辺で「エネルギー」「動力」に言い換えない。用語が決まっている場合は既存の表記に合わせる。
- 画面名、ボタン、補足が同じことを繰り返していたらまとめる。世界観を出す台詞や、明示的に頼まれたキャッチコピーまで機械的に削らない。

## 2. 視覚語彙を使う

| 頼りがちな表示 | まず試すこと |
| --- | --- |
| 画面の真ん中に「燃料が少なくなっています」 | 定位置の燃料計を減らし、帰還ラインに目盛りを置く。補充の判断に必要なら「12%」もその場に出す。 |
| 「左右にスワイプすると回り込めます」を常時表示 | 床に左右の矢印。最初だけ左右へ短く動かし、入力後は静止または非表示。別の入力方式には対応するキーやボタンを出す。 |
| 「鉱石を3個獲得しました」を毎回出す | 鉱石を所持欄へ飛ばし、その欄で「+3」。連続取得は一つに束ねる。 |
| 選んだ装備に「この装備は選択中です」 | 次に操作する候補には枠、装備済みにはチェック。カーソルを動かしてもチェックは前の装備に残す。 |
| 「その場所には置けません」と離れた所に出す | 置く前に半透明の形を見せ、重なったマスに斜線。原因が見た目で分からないなら対象のそばに「電力不足」などを出す。 |
| すべての情報を同じ大きさのカードに入れる | 同時に読む情報は余白と整列でまとめる。よく押す操作を大きく、参照だけの数字は静かに。枠は操作できる物と表示だけの物を見分けるために使う。 |

**位置**は「何のことか」、**形**は「何の種類・状態か」、**大きさと余白**は「何を先に見るか」、**動き**は「何が変わったか」を伝える。大事な状態は、動きが終わっても印や数値で確認できるようにする。

## 3. 残すべき文字は残す

- 初見では意味が割れるアイコンに短いラベルを添える。操作と結果が分かるなら、説明を一段足さない。ホバーでしか読めない補足に必須情報を置かない。
- 価格、残り時間、単位、失うもの、失敗理由と直し方は、判断に必要なら明記する。「素材不足」だけより「鉱石があと3個」。セーブの上書きなら、対象のスロットと取り消せないことを伝える。
- 必須の情報は色・音・動きのどれか一つに預けない。たとえば警告色に形や短いラベルを添える。対応環境ではアイコンボタンに読み上げ名を付け、必要な状態の変化にも音声や振動など状況に合う別の手がかりを用意する。

## 4. ゲームの画面として作る

- 既存画面から枠線、アイコン、文字、余白のルールを拾う。近未来だからネオン、ファンタジーだから金縁、と即決しない。角丸カード、バッジ、グラデーションも、使う理由がなければ足さない。
- プレイ中の画面にメニューと同じ情報量を載せない。慣れても毎回読むものは定位置、初回だけ必要な説明は操作の直前、じっくり読む情報は別画面に分ける。
- 見本の修正は一つずつ積む。前段で燃料計を移したなら、次にボタンの演出を足しても燃料計は戻さない。見た目だけの見本と実際に動く機能を区別し、押せそうな無反応ボタンを残さない。

## 出す前に見るところ

1. ゲーム内の文字だけ読み直す。操作や判断に関係のないコピー、同じ説明の繰り返し、用語の揺れを消す。
2. 一枚止めて、次に押すもの、何に対する表示か、直前から変わった状態を探す。長文を隠した方が迷うなら、先に配置か形を直す。
3. 無音・動き少なめ・狭い画面で、初見の操作から不足時の復帰まで試す。通らない入力方式や確認できていない端末は、確認済みと書かない。

## 参考

作例と「GPT語」の扱いはこのスキルの方針。以下は、言葉選びや操作の伝え方を考えるための公式資料です。

- [Apple Human Interface Guidelines: Writing](https://developer.apple.com/design/human-interface-guidelines/writing)：平易な言葉と、UIで一貫した語調。
- [Xbox Accessibility Guideline 114: UI Context](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/114)：操作前に結果が分かるラベル、操作対象とラベルの近接、読み上げでも伝わる情報。
- [Xbox Accessibility Guideline 103: Audio and visual cues](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/103)：重要な情報を視覚・音声など複数の方法で伝える考え方。
- [Xbox Accessibility Guideline 115: Error messages and destructive actions](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/115)：失敗理由と直し方、取り消せない操作の確認。
